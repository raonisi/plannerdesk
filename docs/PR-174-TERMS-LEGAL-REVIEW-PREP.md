# PR-174 — Terms Legal Review Prep (PR174-A)

**위험도:** Critical · **성격:** 법무 검토 **전달용 초안 후보** — 약관·개인정보·환불·결제 **확정 없음**

## 1. 목적

PR169~PR173 흐름을 바탕으로 법무 검토자에게 전달할 약관·개인정보·데이터 책임·Answer Assistant·오류 제보·환불·결제 관련 **초안 후보**와 **검토 질문**을 한 패킷으로 정리한다. 본 PR은 실제 약관 확정 PR이 아니다.

## 2. 현재 상태

| 구분 | 상태 |
| --- | --- |
| Legal Review Prep | **Conditional Ready** |

| 약관·개인정보 확정 | **Blocked** |
| 환불·결제 정책 확정 | **Blocked** |
| 공개 베타 법무 Go | **Blocked** |
| Critical(정적) | **0** |

연계: PR169 초안 계획 → PR170 결제 구조 → PR171 환불·지원 → PR172 베타 종합 → PR173 공개 준비(work-tools·테스트).

## 3. 확정 금지 원칙

- 모든 법무·개인정보·환불·결제·세무 표현은 **초안 후보**, **검토 필요**, **법무 확인 필요**로 표시한다.
- 확정·준수 완료·검토 완료 주장·즉시 시행 표현은 사용하지 않는다.
- 개인정보 수집 구조 추가, 결제 구현, PG 연동, checkout/billing/subscription, 운영 DB 접근은 포함하지 않는다.

## 13. 법무 검토자에게 전달할 질문

1. PlannerDesk의 서비스 성격을 “보험설계사 업무 보조 도구”로 정의하는 것이 적절한가?
2. public / planner / admin 권한 구분을 약관에 어떻게 반영해야 하는가?
3. 청구서류와 보험사 정보 제공 시 책임 제한 문구는 어느 수준이 적절한가?
4. Answer Assistant를 사용할 때 개인정보 입력 금지와 최종 판단 아님 고지를 어떻게 표시해야 하는가?
5. 오류 제보와 고객지원 기록에서 수집 가능한 최소 정보 범위는 어디까지인가?
6. 향후 유료화 시 전자상거래, 통신판매, 환불, 정기결제 고지 요건은 무엇인가?
7. 결제정보를 직접 저장하지 않는 PG 위임 구조에서 개인정보처리방침에 포함해야 할 항목은 무엇인가?
8. 데이터 오류나 서비스 장애가 환불 또는 보상과 연결되는 기준은 어떻게 정해야 하는가?
9. 보험금 지급 확정 오인을 막기 위해 금지해야 할 표현 범위는 어디까지인가?
10. 공개 베타 전 반드시 선행되어야 할 법무 문서와 고지 화면은 무엇인가?
