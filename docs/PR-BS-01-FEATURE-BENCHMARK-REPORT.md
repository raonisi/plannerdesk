# PR-BS-01 Feature Benchmark Report

## 1. 목적

BohumSchool Archive 공개 사이트는 PlannerDesk의 기능 구조 설계를 위한 기능 벤치마크 참고 대상입니다. PlannerDesk는 외부 사이트를 단순히 복제하지 않으며, 자체적인 도메인 규칙과 설계사 실무 요건에 맞추어 기능을 재구성합니다.
모든 기능과 데이터는 공식 출처 기반으로 별도 수집 및 관리자 검수를 거쳐야 하며, 본 문서는 구체적인 기능 구현이 아닌 향후 로드맵 구상을 위한 문서화 작업입니다.

## 2. 조사 대상과 제한

- 대상: BohumSchool Archive (기능 구조적 관점에 한정)
- 한계: 시스템 아키텍처, 내부 데이터 파이프라인, 설계사 권한별(admin/planner) 관리 기능은 파악 불가

## 3. 복제 금지 원칙

다음 사항은 어떠한 경우에도 복제하거나 무단 수집하지 않습니다.

- **사이트명/브랜드/로고**: 그대로 복제 금지
- **이미지/Asset**: 외부 자산 저장 금지
- **안내 문구**: 외부 사이트 문구 직접 복사 금지
- **보험사 링크 목록**: 외부 사이트의 정리된 링크 목록 직접 이전 금지
- **청구서류**: 서류 원문 및 파일 복제 금지
- **API**: 숨은 API 탐색 및 활용 금지
- **크롤링**: 대량 크롤링 및 무단 데이터 적재 금지
- 오직 공개 페이지에서 보이는 **기능 구조**와 UX 패턴만 참고합니다.

## 4. PlannerDesk 현재 기능과 비교

| 구분 | PlannerDesk (현행) | 외부 벤치마크 사례 | 비교 결과 |
| --- | --- | --- | --- |
| **청구 서류 제공** | 공식 서류 다운로드 제공 (관리자 검수) | 청구 서류 및 링크 제공 | 동일하나 PlannerDesk는 공식 출처 보증 강화 필요 |

## 5. 외부 사이트에서 확인한 기능 유형

- **청구 서류/안내문 다운로드**: 보험사별 필요 서류 제공 기능
- **통합 검색 필터**: 질병명, 서류명, 상황별 상세 필터링 기능
- **오류 제보/피드백**: 잘못된 링크나 낡은 정보 수정 요청 기능
- **보험 업무 도구**: 질병 코드 검색기, 환급금/보험금 계산기 (리스크 높음)
- **모바일 특화 UX**: PWA 또는 홈 화면 추가 유도 기능

## 8. 데이터 모델 확장 후보

이 후보들은 실제 스키마 수정 없이 문서상 검토 단계에 머무릅니다.

- `lastVerifiedAt`: 정보 최신성 보장용 타임스탬프
- `sourceUrl`: 공식 안내 출처 URL
- `reviewStatus`: 데이터 검증 상태 (Draft, Verified 등)
- `officialSourceUrl`: 보험사 공식 약관/자료 URL
- `helpdeskContacts`: 고객센터 연락처 세분화
- `faxNumber`: 팩스 번호 관리 강화
- `cardPaymentInfo`: 카드 납입 지원 정보 (위험도 높음)
- `workLinks`: 설계사 실무 부가 링크
- `correctionRequests`: 오류 제보 처리용 모델
- `plannerFavorites`: 설계사 개인 즐겨찾기 내역

## 9. 리스크 평가

- **Critical (치명적)**
  - 외부 사이트 데이터, 저작권 자료 복제
  - 개인정보 입력 유도
  - 보험금 지급 확정적 표현
  - Public 영역에 검수 전 데이터 노출
  - 보험금/환급금 계산기를 Public에 제공
- **High (위험)**
  - 공식 출처가 불명확한 정보 제공
  - 데이터 최신성 유지 어려움
  - 고객센터/팩스 번호 오안내
  - 카드납/대납 조건 오안내
  - 상병/수술 코드의 청구/지급 가능성 오해 유발
- **Medium (주의)**
  - UX 복잡도 증가 및 기능 비대화
  - 관리자 데이터 관리(입력/검수) 부담 가중
  - 별도 Admin 입력/심사 화면 요구
- **Low (낮음)**
  - 단순 문구 폴리싱
  - 카드 UI 레이아웃 개선
  - Empty State(빈 화면) 안내 문구 개선

## 10. 적용 제외 항목

- **보험금/환급금 추정 계산기**: 사용자에게 확정적 지급 정보로 오인될 법적 위험이 크므로 도입 원천 차단.
- **의료 데이터 진단 분석**: 민감 개인정보(PII) 수집 및 의료 행위 오해 가능성이 있으므로 기획 제외.
- **불명확한 서드파티 링크 모음**: 외부 개인이 운영하는 신뢰할 수 없는 정보 소스로의 연결 배제.

## 12. 다음 1순위 개발 후보

현재 플랫폼의 신뢰도 강화를 위해 가장 시급한 과제는 **"PR-BS-02 Data Freshness UX"** 입니다.
- 정보의 출처(SourceUrl) 명시
- 데이터 검증 일시(lastVerifiedAt) 노출 강화
이 기능은 Public 사용자 및 Planner 모두에게 정보의 안전성과 책임소재를 명확히 하는 데 핵심적 역할을 합니다.

## 13. 최종 결론

BohumSchool Archive 구조 분석을 통해 PlannerDesk에 도입 가능한 UX/기능적 인사이트를 확인했습니다. 그러나 무단 데이터 복제나 리스크(계산기, PII) 유발 기능은 단호히 차단하고, 플랫폼 신뢰성과 설계사 실무 보안을 해치지 않는 범위 내에서 후속 로드맵을 수립했습니다.
차후 작업은 이 리포트를 기준으로 하여, 검증 절차가 포함된 출처 명시 기능(Data Freshness)부터 순차적으로 기획 및 개발되어야 합니다.
