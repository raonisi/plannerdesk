# Knowledge Content Operating Policy
# 지식 콘텐츠 운영정책

## 1. 목적

- 이 문서는 PlannerDesk 지식 아카이브에 등록되는 콘텐츠의 작성, 검수, 공개, 수정, 폐기 기준을 정한다.
- 지식 콘텐츠는 보험설계사의 실무 참고와 업무 정리를 위한 자료다.
- 지식 콘텐츠는 보험금 지급 여부를 판단하거나 손해사정 업무를 대체하지 않는다.
- 지식 콘텐츠는 고객 의료자료나 개인정보를 처리하지 않는다.
- AI 답변 보조의 근거 문서로 사용되려면 `verified` 상태와 안전 기준을 충족해야 한다.

## 2. 콘텐츠 타입별 운영 기준

### A. FAQ

- 반복 질문에 대한 짧은 기준 정리
- 3~5줄 요약 답변 + 상세 설명 구조 권장
- 공식 출처가 필요한 경우 `sourceUrl` 또는 `sourceNote` 필수

### B. 실무 기준

- 업무 판단 순서나 확인 순서를 정리
- “확정 답변”이 아니라 “확인 순서” 중심
- 예: 해지 전 확인 순서, 청구서류 확인 순서, 고지 전 확인 순서

### C. 안내문 샘플

- 설계사가 고객에게 보낼 수 있는 문구 초안
- 보험금 지급 보장, 가입 권유, 공포 조장 표현 금지
- 상황별로 차분하고 중립적인 문장 사용

### D. 체크리스트

- 상담 전 또는 업무 전 확인할 항목 정리
- 예/아니오 판단보다 확인 항목 중심
- 고객 개인정보 입력을 요구하지 않음

### E. 링크 가이드

- 공식 링크, 약관, 공시, 청구양식, 전산 링크 사용 기준
- 비공식 블로그·카페·개인 경험담을 공식 출처로 사용하지 않음

### F. 안전 경계

- PlannerDesk가 하지 않는 것 정리
- 보험금 판단, 손해사정, 의료자료, 개인정보 처리 금지 기준 포함

### G. 운영 가이드

- 관리자 검수, 수정, 폐기, 출처 확인 기준
- 공개 전 검수상태 설정 기준 포함

## 3. 콘텐츠 작성 원칙

- 추측성 답변 금지
- 공식 출처 확인 전 단정 금지
- 보험사별 차이가 있는 경우 “보험사별 기준 확인 필요”로 표시
- 상품별 차이가 있는 경우 “상품별 약관 확인 필요”로 표시
- 고객별 사정이 필요한 경우 “개별 심사 또는 보험사 확인 필요”로 표시
- 보험금 지급 가능/불가 단정 금지
- 보험금 지급 금액 산정 금지
- 의료 진단 해석 금지
- 손해사정 업무처럼 보이는 문장 금지
- 고객 개인정보 또는 의료자료 입력 요구 금지
- 자극적 후킹, 공포마케팅, 과장 표현 금지
- 설계사용 실무 참고 자료임을 유지

## 4. 콘텐츠 구조 표준

각 지식 문서는 아래 구조를 권장한다.

- 제목
- 질문
- 짧은 답변
- 상세 설명
- 확인 순서
- 공식 출처 또는 출처 메모
- 주의사항
- 관련 PlannerDesk 링크
- 고객 안내용 안전 문구
- 금지 표현
- 검수 상태
- 최종 수정일
- AI 참조 가능 여부

## 5. 출처 기준

출처 우선순위:

1순위

- 보험사 공식 홈페이지
- 보험사 공식 약관
- 보험사 공식 청구 안내
- 보험사 공식 상품공시
- 금융감독원 또는 생명보험협회·손해보험협회 등 공식 공시성 자료

2순위

- 내부 운영자가 공식 채널을 통해 확인한 내용
- 관리자 검수 메모

사용 불가 또는 주의:

- 블로그
- 카페
- 커뮤니티 게시글
- 개인 경험담
- 출처 없는 캡처
- 오래된 안내문
- 보험사 직원 구두 설명만 있는 내용

주의:

- 2순위 자료는 `verified` 전환 전 `sourceNote`와 `reviewedBy` 기록이 필요하다.

## 6. 검수 상태 운영 기준

아래 상태는 운영 후보이며, 실제 enum 구현이 아니다.

- `draft`: 작성 중, 공개 불가
- `needs_review`: 검수 필요, 제한적 노출 가능 여부는 기능별 정책에 따름
- `verified`: 공식 출처 또는 관리자 검수 완료
- `archived`: 오래되었거나 대체 문서가 있어 보관
- `rejected`: 공개 부적합

| 상태 | 공개 가능 여부 | AI 참조 가능 여부 |
|---|---|---|
| `draft` | 불가 | 불가 |
| `needs_review` | 기능별 정책에 따라 제한 가능 | 불가 |
| `verified` | 가능 | 가능 |
| `archived` | 기본 비공개 또는 보관 노출 | 기본 불가 |
| `rejected` | 불가 | 불가 |

기준:

- AI 참조 가능: `verified`만
- `needs_review`는 AI 참조 금지
- `draft`는 공개 및 AI 참조 금지
- `archived`는 기본 AI 참조 금지
- `rejected`는 공개 및 AI 참조 금지

## 7. 위험도 운영 기준

아래 위험도는 운영 후보이며, 실제 enum 구현이 아니다.

- `low`: PlannerDesk 사용법, 단순 링크 안내, 즐겨찾기 사용법
- `medium`: 공식 출처 확인이 필요한 실무 정보
- `high`: 고객 응대, 청구, 고지, 심사 관련 주의가 필요한 정보
- `blocked`: 보험금 판단, 손해사정, 의료진단 해석, 개인정보·의료자료 처리 요청

| 위험도 | 작성 기준 | 검수 기준 |
|---|---|---|
| `low` | 간결한 안내 중심 | 기본 검수 + 링크 확인 |
| `medium` | 출처 명시 필수 | 공식 출처 재확인 필수 |
| `high` | 안전 문구·금지 표현 병기 | 관리자 심화 검수 필수 |
| `blocked` | 작성/게시 금지 대상 | 즉시 반려 또는 삭제 검토 |

## 8. 카테고리별 콘텐츠 작성 기준

### 1) 보험사 전산·업무 포털

- 전산 링크, 브라우저, 헬프데스크, 고객센터 안내 중심
- 계정정보, 비밀번호, 내부 전산 우회 방법 안내 금지

### 2) 청구서류·접수 기준

- 필요서류와 확인 순서 중심
- 보험금 지급 가능성 판단 금지
- 고객 의료자료 업로드 요청 금지

### 3) 공시·약관·공식 링크

- 공식 출처 중심
- 약관 해석을 확정적으로 단정하지 않음

### 4) 고객 안내문·응대 문구

- 고객에게 바로 보낼 수 있는 안전 문구 중심
- 지급 보장, 가입 강요, 공포 조장 금지

### 5) 계약관리·유지 실무

- 해지·감액·납입유예 등 선택지와 확인 기준 중심
- 특정 선택을 무조건 권유하지 않음

### 6) 고지·심사 전 확인

- 청약서 질문 기준과 사실 확인 순서 중심
- 가입 가능/거절/할증 여부 단정 금지

### 7) 운영 안전·금지 영역

- 금지 영역과 안전 문구를 명확히 정리
- 서비스 경계 설명

### 8) PlannerDesk 사용법

- 기능 사용법, 검수 배지, 즐겨찾기, 제보 흐름 안내 중심

## 9. 금지 표현

금지 표현:

- 받을 수 있습니다
- 무조건 됩니다
- 지급됩니다
- 지급 안 됩니다
- 보험금은 얼마입니다
- 이 병명은 해당됩니다
- 이 서류면 충분합니다
- 청구하면 나옵니다
- 손해사정 결과상
- 진단상
- 고객 자료를 올려주세요
- 주민등록번호를 입력하세요
- 진단서를 첨부하세요
- 지금 가입해야 합니다
- 모르면 손해입니다
- 100% 보장됩니다

대체 표현:

- 보험사 심사 후 결정됩니다
- 보험사별 기준 확인이 필요합니다
- 상품별 약관 확인이 필요합니다
- 공식 안내 기준으로 확인해야 합니다
- 고객 개인정보와 의료자료는 입력하지 마세요
- 본 자료는 실무 참고용입니다
- 지급 여부와 금액은 PlannerDesk에서 판단하지 않습니다

## 10. 고객 안내문 샘플 작성 기준

고객 안내문 샘플은 다음 기준을 지킨다.

- 고객에게 부담을 주지 않는 문장
- 단정 대신 확인 안내
- 공식 채널 안내
- 개인정보·의료자료를 PlannerDesk에 보내지 말라는 문구 포함 가능
- 지급 여부 보장 금지
- 보험 가입 유도 금지
- 공포 조장 금지

예시 문구 후보:

1. 청구 가능 여부와 지급 금액은 보험사 심사 후 결정됩니다. 먼저 보험사 공식 기준에 따라 필요한 서류를 확인해보겠습니다.
2. 상품별 약관과 보험사 기준이 다를 수 있어, 공식 약관 확인 후 정확히 안내드리겠습니다.
3. 고객 개인정보와 의료자료는 PlannerDesk에 입력하지 마시고, 보험사 공식 접수 채널을 이용해주세요.
4. 안내드리는 내용은 실무 참고용이며, 최종 판단은 보험사 심사 기준에 따라 진행됩니다.
5. 링크가 변경되었을 수 있으니 공식 홈페이지와 공시 자료를 먼저 확인한 뒤 안내드리겠습니다.

## 11. AI 답변 보조 연결 기준

- AI 답변 보조는 `verified` 콘텐츠만 참조한다.
- AI 답변 보조는 `needs_review`, `draft`, `rejected` 콘텐츠를 참조하지 않는다.
- AI 답변은 최종 답변이 아니라 설계사용 초안이다.
- AI 답변에는 근거 문서와 안전 문구가 필요하다.
- AI 답변은 보험금 지급 여부, 지급 금액, 손해사정, 의료진단 해석을 하지 않는다.
- AI 답변이 고객 개인정보나 의료자료 입력을 요구하면 안 된다.
- AI 답변에 사용할 `safeCopy` 필드를 별도로 관리할 수 있다.
- AI 참조 가능 여부는 `aiUsable` 필드 후보로 관리한다.

## 12. 커뮤니티 콘텐츠 승격 기준

- 커뮤니티 글은 자동으로 지식 아카이브가 되지 않는다.
- 우수 답변은 관리자 검수 후 승격 가능하다.
- 출처 없는 개인 경험담은 공식 지식으로 승격하지 않는다.
- 고객 개인정보, 의료자료, 특정 고객 사례가 포함된 글은 승격할 수 없다.
- 커뮤니티 글은 AI 답변 보조가 직접 참조하지 않는다.
- 승격 시 원문을 그대로 복사하지 않고 개인정보·사례·위험 표현을 제거한 운영 문서로 재작성한다.

## 13. 수정·폐기 기준

수정 필요:

- 공식 링크 변경
- 보험사 기준 변경
- 약관 또는 공시 변경
- 오래된 정보
- 표현이 과도하게 단정적인 경우
- 안전 문구가 부족한 경우

폐기 또는 `archived`:

- 공식 출처가 사라진 경우
- 대체 문서가 생긴 경우
- 오래되어 오해 가능성이 큰 경우
- 운영정책 위반 콘텐츠
- 보험금 판단 또는 의료해석 위험이 큰 콘텐츠
